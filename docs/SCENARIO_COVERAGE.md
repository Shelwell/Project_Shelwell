# 场景覆盖矩阵：记忆、上下文与使用体验

> 独立文档，不并入 `MEMORY_CONTEXT_NEXT_TODO.md`。  
> 创建日期：2026-11-10  
> 用途：把“30+ 使用场景”逐条映射到当前实现、优先级与验收标准。  
> 状态只描述当前代码与现有待办，不代表最终产品能力。

---

## 状态说明

| 状态 | 含义 |
|---|---|
| ✅ | 已有实现，且有或应有明确验收 |
| 🟡 | 有底座/部分实现，但体验或边界未验收 |
| ⬜ | 尚未覆盖 |
| P0 | 不做会直接影响核心连续性、隐私或数据正确性 |
| P1 | 长期体验必需，但可在地基后做 |
| P2 | 增强项，可延后 |

> 优先级是建议值，不是现有 TODO 的既有结论。  
> 例如“多 QQ”当前在 TODO 里是 P2，但如果你实际会用多个号，应提升到 P0/P1。

# 十一、最关键的十个缺口

1. **多 QQ → person_id**
2. **known_by / confidential / consent**
3. **QQ 撤回/编辑**
4. **本地时区与相对时间**
5. **并发与崩溃幂等**
6. **摘要溯源与漂移**
7. **topic 选择（多个 active topic）**
8. **旁听消息策略**
9. **工具结果注入防护**
10. **风格宽松与硬红线分离**

# 十二、建议的完成顺序

```text
P0-A 数据正确性
  Scope/Visibility
  tombstone
  删除级联
  时区
  撤回/编辑
  并发/幂等

P0-B 连续性与准入
  MemoryPort
  retrieval planner
  context cache
  C1/C2 持久化
  known_by/consent

P1
  topic/thread
  旁听消息
  只读工具
  摘要溯源
  用户偏好
  安全风格

P2
  多群/多QQ
  媒体
  提醒
  导出/备份
  模型/嵌入切换
  Mnemosyne/API
```

# 十三、完成定义

一个场景算“完成”，至少要有：

- [ ] 代码路径
- [ ] scope/visibility 校验
- [ ] 固定回归测试
- [ ] 重启后测试
- [ ] 隐私泄漏测试
- [ ] 日志/可观测字段
- [ ] 失败降级
- [ ] 写入本文档的验收结果

只有“代码写了”不算完成。

# 十四、维护规则

- 新增场景：追加一行，不覆盖旧结论
- 场景状态变化：更新状态与日期
- 降低优先级：写明原因
- 删除场景：标记 deprecated，不直接删
- 每个 P0 场景必须有对应测试脚本
- 每次完成 P0 阶段，重新评估本表统计
